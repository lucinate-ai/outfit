## Why

outfit's CLI is hand-rolled on the standard `flag` package: a string switch in
`run()` dispatches to per-command `cmdX` functions, each building its own
`FlagSet`, and tab completion is a *second*, hand-maintained description of the
same surface — the `commands` table in `cmd/outfit/complete.go` plus three
embedded shell scripts — that must be kept in step by hand. The drift is real
and already present: flags such as `list --models`, `daemon --api-token-file`,
and `remote start --keep` register fine but never complete. Every new command
or flag needs coordinated edits in several places, and the only safety net is a
test that source-scans `main.go` for `case "…":` lines.

Cobra and Viper are the canonical pair for Go CLIs, and Cobra's built-in
completion engine speaks exactly the `outfit __complete` protocol this codebase
hand-implements. Migrating keeps every completion we have today, makes the
completable surface derive from the registered command tree (so a flag or
command can no longer be forgotten), and gives one home for the repeated
"flag beats env var" resolution that is currently re-implemented per variable.

## What Changes

- **Cobra command tree replaces the hand-rolled dispatch and parsing.** The
  `run()` switch and every `flag.NewFlagSet` in `cmd/outfit` become a Cobra
  command tree with pflag flags. Command names, long and short flag names,
  defaults, and validation behaviour are preserved; the `cmdX` bodies keep
  their logic and read values off the command's flags instead of a `FlagSet`.
- **Viper owns config and env-var resolution.** A single Viper instance
  (root config plus the `OUTFIT_*` environment) replaces the scattered
  `os.Getenv`/flag-precedence lookups in the CLI layer. Precedence stays
  flag > env > config > default. Viper is read-only for outfit's own state:
  `internal/config`'s read-modify-write of `config.json` (unknown keys
  round-trip through `File.extra`) and the alias registry are untouched.
- **Completion migrates onto Cobra's engine.** The hidden `outfit __complete`
  becomes Cobra's native completion protocol (the same one this codebase
  already prints: one candidate per line, a final `:nofile`/`:file`
  directive). The embedded `completion.bash`, `completion.zsh`, and
  `completion.ps1` and the hand-maintained candidate table in `complete.go`
  are removed. `ValidArgsFunction` and `RegisterFlagCompletionFunc` supply the
  dynamic candidates — provider names from the resolved catalogue
  (honouring a `--providers` override already on the line), discovered models
  scoped to the `--provider` already on the line, registered alias names,
  harness names, log levels, and file paths — with the existing
  never-error/never-stderr guarantee.
- **`harness` and its odd flags.** `outfit harness` keeps its byte-for-byte
  argument forwarding via Cobra's `DisableFlagParsing` plus the existing manual
  parse (which moves from `flag` to pflag), so the `--` separator, a leading
  positional naming an Outfit, and bare `--outfit`/`-O` (→ `./Outfit` via
  pflag's `NoOptDefVal`) all behave as today.
- **`fleet` and `remote` become parent commands** with persistent flags and
  their subcommands (e.g. `remote`'s bootstrap, start, pause, stop, status,
  metrics, logs, deploy, env, ls) as real children, instead of a nested
  string switch.
- **Help and version** come from Cobra: per-command `--help`/`-h`, root
  `--version`/`-v`, and the existing `version` subcommand. The hand-written
  `usage()` is dropped.

No change to the Outfit file format, the harness adapters, the daemon control
API, or the provider catalogue. The harness is still a runtime choice, never a
keyword.

## Capabilities

### New Capabilities

None. The observable command/flag surface, outputs, exit codes, and env var
names are unchanged, and the `__complete` protocol this change inherits is
already specified.

### Modified Capabilities

- `shell-completion`: the `outfit completion <shell>` scripts are now
  generated by the CLI framework (Cobra) rather than hand-maintained embedded
  files, and the completion surface is derived from the command tree — the
  "new commands cannot be forgotten" guard becomes a test that walks the
  Cobra tree instead of source-scanning the dispatch, and the surface now
  covers every registered flag (today's table has drifted from it).

## Impact

- `cmd/outfit` — `main.go` (dispatch, `parseSelection`, `usage`), `complete.go`
  (reduced to the dynamic-candidate functions Cobra calls),
  `completion.bash`/`completion.zsh`/`completion.ps1` (removed), plus every
  `cmdX` flag-parsing site, and the completion/CLI test files.
- `go.mod` / `go.sum` — add `github.com/spf13/cobra` and
  `github.com/spf13/viper` (viper transitively pulls afero, cast, mapstructure,
  and fsnotify). This ends the CLI layer's "no runtime dependencies" property;
  the `internal/` domain packages stay free of both.
- `internal/` — minimal and signature-preserving. Packages that receive a
  resolved value from the CLI layer (catalogue path, base URL, key env lookup,
  alias) keep theirs; the CLI layer changes how it obtains the value, not what
  it hands down. `internal/harness` preference resolution (flag > env > stored
  > default, with the source reported) keeps its contract.
- Tests — `complete_test.go` and the completion-coverage guard are rewritten
  against Cobra; per-command tests keep asserting behaviour, not `FlagSet`
  mechanics. Coverage stays >= 80%.
- Docs — AGENTS.md's layout and Traps sections describe the `flag` package, the
  embedded scripts, and `TestCompletionCoversDispatch`; `openspec/config.yaml`
  says "no runtime dependencies". Both need updating.
